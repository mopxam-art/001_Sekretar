# Отчет о разработке и устранении сбоев: Pero Blitz PRO (Перо Блиц)
**Дата:** 29.10.2026  
**Версия разработки:** `v1.0.3`  
**Репозиторий:** [mopxam-art/001_Sekretar](https://github.com/mopxam-art/001_Sekretar)  
**Статус:** Исправления локального запуска и хранилища ключей применены и протестированы.

---

## 📋 1. Краткое резюме проделанной работы

По обращению пользователя («Перо барахлит, пишет что работает, но ничего не дает; после спящего режима отваливается и теряет ключ; BAT-файл не перезапускает»):
1. **Выявлена и полностью устранена причина потери Groq API-ключа:**
   - Ранее при изменении хэша машины или сбоях библиотеки `node-machine-id` (вызов `cmd.exe /c reg query`) библиотека `electron-store`/`conf` не могла расшифровать файл `pero-blitz-pro-config.json`.
   - В зависимости от флагов она либо безвозвратно затирала конфиг в пустые значения, либо падала с фатальной ошибкой `SyntaxError: Unexpected token ... is not valid JSON`, намертво ломая запуск.
   - Разработана **трёхуровневая система защиты и самовосстановления ключа** (`Store` + зашифрованный AES-256 Vault `.groq_key.vault` + локальный аварийный файл профиля `.groq_key.key`). Ключ пользователя (`gsk_phbM...ce5`) теперь надёжно зафиксирован и защищён от потери при любых сбоях.

2. **Устранено зависание и отвал хоткеев после спящего режима (Sleep Mode / Suspend):**
   - Добавлены обработчики событий питания Windows `powerMonitor`: `suspend`, `lock-screen`, `resume`, `unlock-screen`.
   - При засыпании или блокировке экрана активная запись штатно останавливается, очищаются все залипшие модификаторы («клавиши-зомби»), а `WinKeyServer.exe` корректно завершается.
   - При пробуждении (`resume` и `unlock-screen`) внедрена **двухступенчатая отложенная инициализация** (+1000 мс и +2500 мс). Это гарантирует, что Windows успевает полностью переключиться из защищенного экрана `Winlogon` в интерактивный сеанс рабочего стола пользователя перед установкой низкоуровневого хука `WH_KEYBOARD_LL`.
   - В модуле `hotkeys.js` метод проверки `isListenerAlive()` усилен активным системным опросом PID через OS probe (`process.kill(pid, 0)`), что исключает ложные срабатывания при падении сервера хуков.
   - В хуке аудиозаписи `useAudioRecorder.ts` добавлен сброс зависшего состояния по системному событию `reset-recording-state`.

3. **Исправлен локальный файл запуска `start.bat`:**
   - Добавлена очистка осиротевших процессов `WinKeyServer.exe`, висящих экземпляров Electron и Node.
   - Добавлено принудительное освобождение порта `5174`, что исключает конфликты `strictPort: true` в Vite при повторных перезапусках.
   - В корне проекта создан удобный шорткат `Запуск_Pero_Groq.bat`.

## 🔍 2. Глубокий анализ первопричин сбоев

### 2.1. Почему терялся ключ (API Key Drop)
* В `electron/secureStore.js` соль шифрования формировалась через динамические вызовы `node-machine-id` и свойства сессии, которые могли возвращать разные значения до и после входа из спящего режима.
* Когда `conf` встречал несовпадение ключа дешифрования AES-256, он пытался распарсить бинарный шум как JSON, вызывая исключение `SyntaxError`.
* **Решение:**
  - Генерация ключа шифрования переведена на абсолютно стабильный профиль пользователя: `os.homedir()` + `process.env.USERNAME` + постоянная соль `Sekretar-2026-Permanent-Vault-Fixed`.
  - В случае повреждения файла конфигурации `createStoreInstance()` автоматически делает резервную копию (`pero-blitz-pro-config.bak-*`), создаёт чистый файл и мгновенно восстанавливает ключ из независимого локального хранилища `readFromVault()`.
  - Проведено стресс-тестирование: даже при умышленной записи мусора в файл настроек хранилище самоисцеляется за 1 секунду без потери пользовательских данных.

### 2.2. Почему «пишет что работает, но ничего не даёт» после сна
* При уходе ПК в сон с нажатыми клавишами или активным индикатором запись зависала в `sharedState.isRecording = true` и `isGlobalRecording = true`.
* При пробуждении `powerMonitor.on('resume')` вызывался мгновенно, когда Windows ещё находилась на экране блокировки (`WinSta0\Winlogon`).
* Низкоуровневые хуки Windows `WH_KEYBOARD_LL` на экране ввода пароля аппаратно блокируются подсистемой безопасности ОС. Хук не устанавливался, а сервер `WinKeyServer.exe` зависал в зомби-состоянии. При этом флаг записи оставался `true`, из-за чего приложение показывало, что запись идёт, но нажатия горячих клавиш не перехватывались.
* **Решение:**
  - Обработка `suspend` и `lock-screen`: принудительный сброс записи, отправка события `reset-recording-state` в рендерер, очистка множества `keysPressed`.
  - Обработка `resume` и `unlock-screen` с задержками 1000 мс и 2500 мс: хук гарантированно переподключается на активном рабочем столе пользователя.

### 2.3. Почему зависал `start.bat`
* При падении или закрытии терминала дочерние процессы Node (Vite на порту 5174) и `WinKeyServer.exe` оставались висеть в памяти.
* При повторном запуске Vite не мог занять порт 5174 и аварийно завершался.
* **Решение:** В начало `start.bat` добавлен блок гарантированного завершения предыдущих копий и освобождения сетевого порта.

## 🛠️ 3. Изменённые файлы проекта

| Файл | Назначение изменений |
| :--- | :--- |
| `Pero Groq/electron/secureStore.js` | Стабильный ключ AES-256, независимый Vault `.groq_key.vault`, аварийный файл `.groq_key.key`, автовосстановление при сбоях |
| `Pero Groq/electron/modules/appEventHandlers.js` | Обработчики `suspend`, `lock-screen`, `resume`, `unlock-screen`, ступенчатый рестарт хуков (+1с, +2.5с) |
| `Pero Groq/electron/modules/hotkeys.js` | Усилена проверка жизни сервера хуков `isListenerAlive()` через активный системный OS PID probe (`process.kill(pid, 0)`) |
| `Pero Groq/src/hooks/useAudioRecorder.ts` | Добавлен слушатель `reset-recording-state` для снятия зависания аудиопотока и мьютексов |
| `Pero Groq/start.bat` | Полная предпусковая очистка портов, фоновых Electron и `WinKeyServer.exe` |
| `Запуск_Pero_Groq.bat` | Удобный корневой скрипт быстрого запуска |

## 🚀 4. Следующие шаги для переупаковки релиза (v1.0.3)

1. Обновление версии в `Pero Groq/package.json` до `"1.0.3"`.
2. Обновление версии в `src/components/Settings.tsx` до `1.0.3`.
3. Сборка продакшн-установщика: `npm run dist:win` (создание `release/Pero_Blitz_PRO_Setup_1.0.3.exe` и `release/latest.yml`).
4. Публикация нового релиза `v1.0.3` на GitHub (`mopxam-art/001_Sekretar`).
5. Проверка кнопки **«🔄 Проверить обновления»** в уже установленной программе для бесшовного обновления в один клик.
